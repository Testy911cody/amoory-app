## 1. Purpose

Use **tmux** for long-running UI work — dev servers, build loops, deploy watches, test iterations — so sessions survive terminal disconnects and can be monitored without blocking Cursor.

**Division of labor**

| tmux Claude | Cursor Agent |
|-------------|--------------|
| Multi-file UI edits in scoped `public/` paths | Schema, Supabase, build scripts, env |
| Run `npm run dev` / `build` / lint inside scope | Review diff, regressions, commit, push, CI |
| Extended polish in one UI area | Deploy only when user explicitly asks |

---

## 2. When to use tmux

Use a detached tmux session when any of these apply:

- Multi-step UI refactors spanning many files (`public/src/**`, `public/src/styles.css`)
- `npm run dev` / `npm run build` / `cap sync` loops
- `gh run watch` or other deploy pipeline watches (>2 minutes)
- Any task expected to run **>2 minutes** or **>15 minutes** of sustained editing

**Do not use tmux for:** quick one-file fixes, schema/migrations, secrets (`.env.local`), git push/force-push, or deploy triggers unless the user explicitly authorizes.

---

## 3. Session naming

| Session name | Use for |
|--------------|---------|
| `agent` | Default Claude Code session (global convention) |
| `talkboard-ui` | Talk Board UI refactors, dev server, build loops |
| `talkboard-deploy` | `sync:amoory`, `gh run watch`, production smoke checks |

List / attach:

```powershell
tmux ls
tmux attach -t talkboard-ui
```

Kill when done:

```powershell
tmux kill-session -t talkboard-ui
```

## 4. Commands (Windows — PowerShell)

**User OS:** Windows 10+. Refresh PATH if `tmux` or `claude` not found:

```powershell
$env:Path = [System.Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("Path","User")
tmux -V
claude --version
```

### If WSL or Git Bash is available

Standard tmux works inside WSL/Linux:

```bash
tmux new -s talkboard-ui -d
tmux attach -t talkboard-ui
# inside: cd to AmooryApp root, then: claude
# detach: Ctrl+B, then D
```

### Native Windows (no WSL)

- **Preferred:** [tmux-windows](https://github.com/arndawg/tmux-windows) via `winget install -e --id arndawg.tmux-windows`
- **Alternative:** Windows Terminal split panes, or Cursor background shells (session dies if tab closes)
- **Fallback:** Claude Code VS Code extension (`Anthropic.claude-code`) — same scope rules, no tmux

### Practical patterns

```powershell
# Create detached session (first time)
cd "C:\Users\sudan\Desktop\VSCODE - Copy\Projects\AmooryApp"

# Attach, start Claude, paste directive prompt
```

## 8. Feedback loop

When UI patterns, file layout, or workflow change:

1. Update **this file** (`feedback/agent/CLAUDE_DIRECTIVE.md`) with new scope, paths, or verify steps.
2. Add dated notes under `feedback/agent/` (e.g. `feedback/agent/2026-06-22-ui-notes.md`) for task-specific handoff.
3. Cursor Agent integrates changes, runs verify, and commits when the user asks.

### Report-back format (tmux Claude → Cursor)

When finished or blocked, report:

1. **Files changed** — bullet list under `public/src/` (and any other touched paths)
2. **Verify** — `npm run build` pass/fail; manual smoke notes if run
3. **Blockers** — env, design decisions, schema needs
4. **Sync status** — whether HouseGames `sync:amoory` was run (Cursor usually owns sync/deploy)
